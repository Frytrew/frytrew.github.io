# 📘 Инструкция: редактор сайта, фото и публикация на GitHub Pages

## Из чего состоит сайт

| Файл | Зачем нужен |
|---|---|
| `index.html` | Сам сайт + встроенный визуальный редактор. Загружается на GitHub **один раз** |
| `content.js` | Всё содержимое сайта (тексты, ссылки, проекты). Создаётся редактором. **Меняете только его** |
| `photo-sample.jpg` | Фото в первом экране (сейчас там абстрактная картинка-пример) |
| `ИНСТРУКЦИЯ.md` | Этот файл (на сайт загружать не нужно) |

---

## Часть 1. Визуальный редактор ✏️

### Как открыть

Откройте сайт и добавьте к адресу `?edit=1`:

- **Локально:** откройте `index.html`, затем в адресной строке допишите `?edit=1` → например: `file:///C:/Users/.../portfolio/index.html?edit=1`
- **После публикации:** `https://ваш-логин.github.io/portfolio/?edit=1`

Появится окно **«🔐 Введите пароль»** (при самом первом входе — «Придумайте пароль»). После ввода справа откроется панель **«Редактор сайта»** (на телефоне — кнопка «✏️ Редактор сайта» слева внизу).

### Как работать

1. Раскрывайте разделы панели: **Дизайн и цвета, Фото, Шапка и меню, Первый экран, Цифры, Услуги, Портфолио, О себе, Контакты, Футер**.
2. Меняйте поля — сайт слева **обновляется мгновенно**.
3. Лишние блоки можно отключить галочкой «Показывать блок».
4. Списки (кнопки, проекты, работы, услуги…) — добавляйте кнопкой «+ Добавить…», удаляйте крестиком ✕.
5. Ваши правки автоматически запоминаются в браузере как черновик (можно закрыть страницу и продолжить потом).

### Как сохранить изменения навсегда

1. Нажмите **💾 Скачать content.js** — файл попадёт в загрузки.
2. Положите его **рядом с index.html** (замените старый, если был).
3. Для опубликованного сайта — загрузите новый `content.js` в репозиторий GitHub (см. Часть 3).

> ⚠️ Пока вы не скачали и не положили `content.js` рядом — изменения видны только вам и только в этом браузере (это черновик).

Кнопка **↺** в панели — сброс всех правок к исходному виду.

### Если хотите править текстом вручную

`content.js` — обычный текстовый файл, его можно открыть в блокноте или VS Code и править напрямую. Структура повторяет `DEFAULT_CONFIG` внутри `index.html`.

## Часть 2. Пароль на редактор (админка) 🔐

### Задать пароль

1. Откройте сайт с `?edit=1`.
2. При первом входе появится окно **«Придумайте пароль»** — введите пароль дважды (минимум 4 символа; индикатор подскажет, насколько он надёжный).
3. Готово — теперь редактор открывается только по паролю.
4. **Обязательно нажмите «💾 Скачать content.js»** и сохраните его рядом с `index.html` / загрузите в GitHub — пароль хранится именно там (в виде хеша).

После правильного ввода редактор не спрашивает пароль повторно в течение выбранного времени (по умолчанию 2 часа; настраивается в панели → «Админка (пароль)»).

### Сменить или убрать пароль

В панели редактора → раздел **«🔐 Админка (пароль)»**: введите новый пароль дважды → «Сохранить пароль». Там же — кнопка «Убрать пароль» и настройка времени сессии. Не забудьте скачать новый `content.js`.

### Забыли пароль?

- **Локально:** откройте `content.js` в блокноте, найдите строку `"passwordHash": "sha256$..."` и замените значение на `""` (пустые кавычки). После обновления страницы редактор предложит придумать пароль заново. Если `content.js` нет — нажмите ↺ (сброс) в окне редактора.
- **На опубликованном сайте:** скачайте `content.js` из репозитория GitHub, обнулите `passwordHash` как описано выше, загрузите файл обратно.

### Важно про безопасность (честно)

- Пароль **не хранится в открытом виде** — только SHA-256 хеш. По хешу пароль не восстановить.
- После 5 неверных попыток ввод блокируется на 30 секунд, после 10 — на 5 минут.
- Но помните: на статическом сайте (GitHub Pages) любая клиентская защита — это «замок от честных людей»: исходный код страницы доступен всем, и очень упорный человек может обойти окно пароля через консоль браузера.
- **Что реально защищает ваш сайт:** опубликованный контент посетители изменить не могут в принципе — правки в редакторе сохраняются только в браузере того, кто их вносит, и на сайт попадают лишь когда вы сами загрузите новый `content.js` в репозиторий. Главная защита — пароль от вашего GitHub-аккаунта (включите там двухфакторную аутентификацию).
- Если нужна настоящая приватность (например, черновик сайта «только для своих») — можно закрыть весь сайт паролем на уровне хостинга (например, Netlify/Vercel с парольной защитой) или сделать репозиторий приватным (Pages на приватных репозиториях доступен на платных тарифах GitHub).

## Часть 3. Фото в первом экране 🖼

Сейчас в рамке с градиентом стоит абстрактная картинка-пример (`photo-sample.jpg`) и два «плавающих» бейджа.

### Вариант А — своё фото файлом (рекомендуется)

1. Подготовьте фото. Идеально: **портретное, пропорции примерно 4:5** (например 880×1100 px), JPG, до ~500 КБ. Лицо крупно, фон спокойный — тогда оно лучше всего смотрится в рамке.
2. Сохраните его как `photo.jpg` рядом с `index.html`.
3. В редакторе (?edit=1) → раздел **«Фото»** → поле «Файл или ссылка» → напишите `photo.jpg` → скачайте `content.js`.
4. Загрузите `photo.jpg` и новый `content.js` в репозиторий.

Рамка сама обрежет фото под пропорции 4:5 — ничего подгонять не нужно. Если файла не окажется на месте, автоматически покажется красивая заглушка с инициалами.

### Вариант Б — загрузить прямо в редакторе

В разделе **«Фото»** нажмите **«📤 Загрузить с компьютера»** и выберите файл. Фото «вшивается» в content.js (файл станет тяжелее — до 2–3 МБ, для GitHub это нормально).

### Вариант В — оставить заглушку

Очистите поле «Файл или ссылка» — останется стильный градиентный блок с инициалами (меняются в поле «Инициалы»).

### Бейджи вокруг фото

В разделе «Фото» → «Плавающие бейджи» можно менять текст, эмодзи и угол расположения («Санкт-Петербург», «40+ текстов» и т.д.).

## Часть 4. Публикация на GitHub Pages 🚀

### Шаг 1. Аккаунт

Зарегистрируйтесь на [github.com](https://github.com/signup) (бесплатно), если аккаунта нет.

### Шаг 2. Репозиторий

1. **+** в правом верхнем углу → **New repository**.
2. **Repository name**: `portfolio`.
   > 💡 Если назвать репозиторий `ваш-логин.github.io` — сайт будет по короткому адресу без суффикса.
3. **Public** → галочка **Add a README file** → **Create repository**.

### Шаг 3. Загрузка файлов

1. В репозитории: **Add file → Upload files**.
2. Перетащите: `index.html`, `content.js` (если уже редактировали), `photo.jpg` / `photo-sample.jpg`.
3. **Commit changes**.

### Шаг 4. Включить Pages

1. **Settings** → слева **Pages**.
2. **Source**: `Deploy from a branch` → **Branch**: `main`, `/(root)` → **Save**.
3. Через 1–3 минуты на этой же странице появится адрес сайта: `https://ваш-логин.github.io/portfolio/`

### Шаг 5. Обновление сайта после правок

1. Поработали в редакторе → **💾 Скачать content.js**.
2. В репозитории: **Add file → Upload files** → загрузите новый `content.js` поверх старого → **Commit changes**.
3. Через 1–2 минуты сайт обновится. `index.html` перезагружать не нужно (только если меняли его вручную).

> 🔒 Редактор на опубликованном сайте видят только те, кто сам добавит `?edit=1`, и их правки остаются только у них в браузере. Для посетителей сайт обычный.

### (Необязательно) Свой домен

1. **Settings → Pages → Custom domain** → введите домен (например `ruslanmoroz.ru`) → Save.
2. У регистратора домена добавьте DNS-записи, которые покажет GitHub (A-записи на `185.199.108.153` и др., либо CNAME на `ваш-логин.github.io`).
3. После привязки включите **Enforce HTTPS**.

## Частые проблемы

| Проблема | Решение |
|---|---|
| Правки в редакторе не сохраняются на сайте | Вы не скачали `content.js` или не положили его рядом с `index.html` / не загрузили в GitHub |
| Забыл пароль от редактора | Обнулите `"passwordHash"` в `content.js` (подробно — в Части 2) |
| Редактор блокирует ввод после нескольких попыток | Это защита от подбора: подождите 30 секунд (или 5 минут после 10 попыток) |
| Фото не отображается | Проверьте имя файла в разделе «Фото» (регистр букв важен: `Photo.jpg` ≠ `photo.jpg`) |
| Сайт пустой / белый экран | Ошибка в `content.js` — удалите его (вернётся встроенное содержимое) или нажмите F12 → Console, посмотрите номер строки |
| Изменения не видны после загрузки в GitHub | Обновите страницу с очисткой кэша: **Ctrl+F5**; подождите 1–2 минуты |
| 404 | Файл должен называться ровно `index.html`; Pages должен быть включён (Settings → Pages) |
| Хочу вернуть всё как было | Кнопка ↺ в редакторе; или в GitHub: файл → **History** → восстановить старую версию |
